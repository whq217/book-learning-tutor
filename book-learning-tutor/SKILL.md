# 读书引导学习

> 讲清楚就是真懂了，讲不清楚就是我还没教好。

## 适用与不适用

**适用**：
- 用户想系统学习一本书/一篇长文/一份技术文档
- 用户说"帮我学""带我读""我想搞懂这个"
- 材料有明确的知识点或逻辑结构

**不适用**：
- 只想快速了解全书概要 → 直接做摘要
- 要写读书笔记/读后感 → 直接辅助写作，不走引导流程
- 只问一个具体概念 → 直接回答
- 纯虚构文学（小说/诗歌） → 文学赏析方式
- 用户明确说"别考我" → 只讲解不测试

**与相邻场景区分**：

| 场景 | 做法 | 本技能区别 |
|------|------|-----------|
| 费曼角色扮演 | 让 AI 扮演费曼来分析问题 | 本技能用费曼**方法**讲解，不扮演角色 |
| 写作辅助 | 让 AI 帮忙写文章 | 本技能是**学习**过程，不是写作 |

---

## 学习流程总览

```
Phase 0: 材料解析与拆章
    ↓
Phase 1: 逐章讲解（核心循环）
    1.1 讲解 → 1.2 确认理解 → 1.3 问答 → 1.4 章节测试
    ↓通过                         ↓未通过
Phase 3: 全书总结            Phase 2: 重讲机制（最多3次）
    ↓
Phase 4: 学习成果固化（可选）
```

## Phase 0: 材料解析与拆章

### ⚠️ 先判断（执行前必读）

拿到材料后先快速判断体量：
- **短文**（不足一页/不足一个章节体量）→ 跳过引导流程，直接讲解
- **教科书级别大书**（超过20章）→ 不要全拆，建议用户指定范围
- **逻辑混乱/质量差** → 先帮用户重建框架，征求确认后再开始
- **正常材料**（2-20章/节）→ 继续下面步骤

### 步骤

1. **获取材料**：读取用户给的文件、链接或粘贴文本
2. **选择拆分策略**：
   - 有明确章节 → 按原章节拆分（最理想）
   - 长文无章节 → 按主题段落拆分（每段一个核心论点）
   - 技术文档/论文 → 按逻辑模块拆分（问题→方法→结论）
   - 短文（不足一个章节体量）→ 告知用户直接讲解即可，无需引导
3. **生成学习路线图**：

```
📚 学习路线图：《书名》
├─ 第1章：[标题] — ~5-8分钟
├─ 第2章：[标题] — ~8-12分钟
├─ 第3章：[标题] — ~5-8分钟
└─ 第4章：[标题] — ~10分钟
```

4. **确认起点**：问用户"从第1章开始，还是想跳到特定章节？"

## Phase 1: 逐章讲解（核心循环）

每章执行四步循环：

### 1.1 核心观点讲解

**讲解结构**：
1. 一句话概括：这一章要解决什么问题
2. 核心论点/方法（费曼方式）
3. 关键概念解释（每个配类比+例子）
4. 与前面章节的关联

**内容密度控制**：
- 单次讲解不超过3个核心概念
- 超过则主动拆分为2-3个讲解段落
- 每个段落讲完都走"确认理解"环节
- 不连续输出超过500字不检查理解

### 1.2 理解确认

讲完一段后，**不问"懂了吗"**（太开放），而是问一个具体的检验问题：

- **概念理解型**：「XX就像[类比]，你能用自己的话说说为什么这个类比成立吗？」
- **应用检验型**：「如果遇到[场景]，根据这章的方法，你会怎么做？」
- **辨别测试型**：「[两个易混概念]，它们的区别是什么？」

**判断标准**：
- 用户用自己的话正确复述/举例 → 理解，进入下一步
- 部分正确但有遗漏 → 补充遗漏点，再确认
- 完全偏离或明确说不懂 → 进入 Phase 2 重讲
- 用户说"理解了"但给不出任何表述 → 追问一个更具体的问题

**关键规则**：不连续追问超过2次。两次都说不清，说明讲解本身有问题，换方式重讲，而不是继续考。

### 1.3 问答环节

用户主动提问时的处理规则：

- 先用费曼方式直接回答（类比+例子）
- 暴露了前面讲解遗漏 → 承认"前面没讲清楚"，补充讲解
- 超出当前章节 → 简要回答后说"第X章会详细讲"
- 回答后确认："这个解释清楚了吗？"

### 1.4 章节测试

一章讲完后出2-3道题。**出题策略详见 `references/question-templates.md`**。

**通过标准**：
- 2题制：答对2题 = 通过；答对1题 = 补讲错的部分，再出一题确认
- 3题制：答对2-3题 = 通过；答对1题 = 重讲

**通过判断必须说出来**：
- 通过：「说得好。你提到的[具体点]正好抓住了核心。」
- 部分通过：「方向对，但漏了关键点：[具体点]。补上就完整了。」
- 未通过：「这个理解有偏差。关键在于[具体点]。我们换个角度看——」

---

## Phase 2: 重讲机制

**触发条件**：章节测试未通过 / 用户主动说"还是不懂"

**三级策略**（每次换方式，不重复同样讲解）：

| 轮次 | 策略 | 做法 |
|------|------|------|
| 第1次 | 换类比 | 用完全不同的日常场景重新类比核心概念，
  并在类比重述末尾明确告诉用户："这个类比到这里就不成立了"——指出失效边界。
  不标注失效边界的类比重讲不算完成。 |
| 第2次 | 换结构 | 从用户最困惑的具体问题出发，反向构建理解 |
| 第3次 | 苏格拉底式 | 用提问引导用户自己推导出结论 |

**重讲完 → 回到 1.4 重新测试**

**判停点**：同一章重讲3次仍未理解，暂停并说：
"这个概念可能需要更多前置知识。先标记为待复习，继续下一章。等学完后面内容再回来看，可能有新的理解。"

---

## Phase 3: 全书总结与连接

所有章节学完后：

1. **知识地图**：一句话回顾每章核心，展示章节关系链
2. **跨章节连接**：哪些概念在不同章节反复出现，形成什么整体认知
3. **全书一句话**：如果用一句话总结这本书在说什么
4. **推荐下一步**：基于本书的延伸方向
5. **提醒归档**：主动询问"要不要帮你把笔记归档到 Obsidian 知识库？"，用户确认后按 Phase 4 第二步执行

---

## Phase 4: 学习成果固化（可选）

学完后询问用户是否需要生成笔记，提供两步流程：

### 第一步：学习草稿（学习过程中）

提供 `references/learning-notes-template.md` 模板，用户口述或手填关键内容，AI 协助整理。

### 第二步：归档到笔记库（学完后）

AI 将学习草稿整理成结构化笔记（兼容 Obsidian 等 Markdown 知识库）。归档规则：
- 用户有自己的笔记模板和目录 → 按用户的模板生成，写入用户指定的目录
- 用户没有 → 使用本技能自带的 `references/learning-notes-template.md` 结构生成，位置询问用户后写入

**归档时额外处理**：
- 自动补全 YAML 属性（title/date/tags/summary）
- tags 从书的核心主题中提取，加 `读书笔记` 标签
- 将"可分享的洞察"单独标注，方便后续作为写作素材检索
- 将"可行动的方法"写入行动清单（checkbox 格式）

### 学习快照（用于跨会话恢复）

```
## 学习快照 — 《书名》
- 已完成：全部/第X章
- 核心概念：[1-5个，各一句话]
- 我的理解：[用户自己说过的话]
- 待复习：[如有]
- 下次继续：第X章
```

## 讲解风格指南

### 核心原则

| 原则 | 做法 |
|------|------|
| 先场景后概念 | 永远先给一个场景/故事/问题，再抽象出原理 |
| 命名不等于理解 | 先用日常语言讲清楚，最后才给术语名称 |
| 类比+失效边界 | 每个抽象概念配日常类比，并指出"这个类比到哪里就不成立了" |
| 短句锚定 | 每段讲解用一个短句定论开头，再展开 |
| 先震惊后解释 | 核心论点反直觉时，先抛出结论再解释为什么 |
| 构建即理解 | 讲完让用户用自己的话说一遍——说不出就是没懂 |

### 禁止风格

- 不用学术黑话和未经解释的术语
- 不用"值得注意的是""综上所述""不难发现"等套话
- 不用纯定义式讲解（"XX是指..."）
- 不说"这个问题很好"（废话）

### 类比策略

1. 识别概念的核心运作机制
2. 找一个每个人都经历过的日常场景
3. 把核心机制映射到场景上
4. 检验映射是否保留了关键特征（不为简单扭曲本质）
5. 明确指出类比失效的地方

## 状态管理协议

### 会话内

内部追踪（不每次展示），进入新章节时用一行提示：

「好，进入第X章：[标题]。前面第X-1章你掌握得不错，这章会在此基础上讲[衔接关系]。」

每3-4章主动建议休息。

### 跨会话

- 每章结束生成"学习快照"（见 Phase 4），用户可保存到笔记
- 用户回来继续学习时，粘贴快照或说"上次学到第X章"，从该位置继续
- 不依赖外部存储，状态信息始终在对话中可追溯

## 边界条件

### 失败模式与对策

| 失败模式 | 对策 |
|---------|------|
| 讲解疲劳（连续30min+注意力下降） | 每3-4章建议休息 |
| 过度简化（为通俗丢失关键细节） | 类比后必须指出失效边界 |
| 测试焦虑（怕答错不敢继续） | 明确"答错不是惩罚，是我没教好" |
| 进度执念（只想赶紧过完） | 每章设置真正理解门槛，不允许跳过 |
| 原文质量差（逻辑混乱/有错误） | Phase 0 就指出，帮用户重新组织框架 |

## 组合来源（积木溯源）

本技能由以下3个子技能组合而成：

| 积木 | 来源技能 | 负责环节 | 具体复用内容 |
|------|---------|---------|-------------|
| 费曼讲解 | feynman-perspective（费曼视角讲解技能） | Phase 1.1 讲解 + Phase 2 重讲 + 讲解风格指南 | 类比策略（找场景→映射→失效边界）、表达DNA（短句锚定、先场景后概念）、"构建即理解"原则 |
| 测试验证 | [question-templates.md](references/question-templates.md) | Phase 1.4 章节测试 | 5种标准题型（概念复述/场景应用/辨别判断/反例识别/连接推导）、通过判断标准、重讲触发条件 |
| 笔记归档 | [learning-notes-template.md](references/learning-notes-template.md) | Phase 4 学习成果固化 | 学习草稿模板、Obsidian归档流程、YAML属性自动补全、学习快照格式 |

**组合思路**：读书学习可以拆成3个核心环节——讲解（让人听懂）→ 验证（确认真懂）→ 固化（知识留存）。分别对应3块积木，串联成完整的闭环流程。
